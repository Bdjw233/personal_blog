模型的上限由数据和算力共同决定，但真正拉开差距的往往是数据。同样一份网页抓取、同样一次微调，语料处理做得细不细，结果能差出一个档位。

我在浩鲸云计算的大数据 / 大模型数据岗位做了八个月，主要工作就是语料整理、清洗和预处理。这篇按流水线的顺序，把每一步的具体做法、判断标准和踩过的坑写下来。

## 一条流水线长什么样

把语料当成一个数据管道，而不是一次性的脚本，是最重要的心态转变。整条链路可以拆成五段：

**采集 → 规范化 → 去重 → 过滤 → 配比与打包**

每一段的输出都应该是可校验、可回滚的中间产物。这样当训练效果不对时，你能定位到「问题出在去重太狠」还是「某个来源的噪声没清掉」，而不是面对一堆混合后的数据束手无策。

## 一、规范化：先把同一件事写成同一种样子

规范化的目标不是"好看"，而是让后续所有规则只面对有限的形式。

常见的脏数据：

| 类型 | 例子 | 处理方式 |
| --- | --- | --- |
| 全角/半角混用 | `ＡＩ（２０２５）` | Unicode NFKC 归一 |
| 多余空白与换行 | 连续 5 个空行、行尾空格 | 折叠空白，保留段落边界 |
| HTML 残留 | `&nbsp;`、`<div>` 片段 | 实体解码后剥离标签 |
| 控制字符 | `\x00`、零宽空格 | 白名单过滤 |
| 编码错乱 | `æ–‡æœ¬` | 检测并丢弃，不要试图修复 |

有一个容易被忽略的点：**规范化必须在去重之前做**。否则同一个文档的两种写法会被当成两篇，去重率虚低，训练时又被重复喂了一遍。

## 二、去重：分三层做，不要一刀切

去重是收益最大、也最容易做过头的一步。我一般分三层：

1. **精确去重**：对规范化后的文本取 SHA-1，直接丢弃重复项。成本极低，先跑一遍。
2. **近重复去重**：SimHash 或 MinHash + LSH。网页转载、模板页、同一份文档的多次发布都在这一层被抓住。
3. **段落级去重**：长文档里反复出现的免责声明、导航文案、版权尾注。

第三层很多人会漏。一篇文章 80% 是正文、20% 是尾注，如果只做文档级去重，这些尾注会在成千上万篇里重复出现，模型会把它们当成高频知识背下来。

这里的坑是阈值。SimHash 的汉明距离卡得太松，会把同一主题的不同文章判成重复，数据量断崖式下跌；卡得太紧，模板页又清不干净。我的做法是先人工标注 200 对样本，画出准确率/召回曲线，再定阈值，而不是凭感觉拍一个数字。

## 三、过滤：规则先行，模型兜底

过滤规则按成本从低到高排：

- **长度**：过短（< 50 字）和过长（> 50k 字）的文档通常都不是正常内容。
- **语言**：用轻量语言识别，丢弃与目标语种不符的文档。多语种语料则要保留语言标签，不要在配比阶段才发现混进了别的语言。
- **符号比例**：标点、数字、特殊字符占比过高的，多半是表格残渣或乱码。
- **重复 n-gram 比例**：一篇文档内部重复片段过多，通常是采集事故。
- **困惑度**：用一个小模型给文档打分，过滤明显不通顺的文本。这一步成本高，放在最后。

规则的好处是快、可解释、可回滚；坏处是容易误杀。所以每条规则都要记录**丢弃数量和丢弃原因**，定期抽样看看被丢掉的是什么。曾经有一条"数字占比 > 30% 丢弃"的规则，把一批技术文档里的金融数据章节全清掉了，发现时已经是第二轮训练之后。

## 四、预处理：样本构造与配比

清洗完还不等于能训练，还要按训练目标构造样本：

- **截断**：按 token 截断而不是按字符。中文一个字符约等于 0.6–1 个 token，混着英文时按字符截会截出奇怪的长度分布。
- **拼接与打包**：多条短样本打包进同一个序列可以提高吞吐，但要注意用分隔符隔开，并处理好 attention mask，别让模型学到"两段无关文本应该连在一起"。
- **配比**：不同来源按权重采样。代码、百科、对话、网页的合理比例和任务强相关，通常要跑几组小规模消融实验来定。
- **去偏**：某个来源占比过高会让模型口吻单一，表现为"回答什么都像同一个人写的"。

## 五、可复现：让脚本替你做重复劳动

流水线里最耗人的其实不是算法，而是反复的人工核对。我后来的做法是把所有判断都写成脚本和校验规则：

```python
import hashlib
import unicodedata

def normalize(text: str) -> str:
    text = unicodedata.normalize('NFKC', text)
    text = text.replace('\u200b', '').replace('\ufeff', '')
    lines = [line.strip() for line in text.splitlines()]
    return '\n'.join([line for line in lines if line])

def exact_hash(text: str) -> str:
    return hashlib.sha1(text.encode('utf-8')).hexdigest()

def dedup(docs):
    seen, kept, dropped = set(), [], 0
    for doc in docs:
        h = exact_hash(normalize(doc))
        if h in seen:
            dropped += 1
            continue
        seen.add(h)
        kept.append(doc)
    return kept, dropped

docs, dropped = dedup(raw_docs)
print(f'保留 {len(docs)} 条，丢弃 {dropped} 条重复')
```

每个脚本都输出一份统计：输入条数、保留条数、各条规则的丢弃分布、token 长度直方图。这批数字就是数据集的"体检报告"，比任何口头描述都有说服力。

## 复盘

如果让我给刚开始做语料的人三条建议：

1. **先量后改**。在动手清洗之前，先把数据分布画出来，知道脏在哪，再写规则。
2. **一切可回滚**。每一阶段的产物单独落盘，版本号写清楚。出了问题能退回上一步，比重新跑一遍省钱得多。
3. **人工抽样不能省**。自动化指标只能告诉你"变了多少"，不能告诉你"变得对不对"。每轮至少抽 100 条读一遍。

语料工作听起来不性感，但它是模型能力的地基。把"能跑"的数据变成"能交付"的数据集，是我在这段实习里最大的收获。
