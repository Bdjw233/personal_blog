2025 年 5 月到 11 月，我在高邮一家新材料公司做网络安全运维实习。工作内容听起来很"传统"：给终端打补丁、更新病毒库、排查弱口令、看异常外联、维护防火墙和上网行为策略、按需开通和回收账号权限。

半年下来，最大的收获不是学会了某个安全产品，而是**换了一个视角看自己写的代码**。

## 日常到底在做什么

一天的巡检大致是这些：

- 查终端和服务器的补丁状态、病毒库版本，记录未完成的项。
- 扫一遍账号：有没有长期不用的账号、有没有权限过大的账号、有没有共享账号。
- 看外联日志：哪些内网主机在往陌生地址发数据。
- 处理告警与报修：员工点了钓鱼链接、装来源不明的软件、打印机连不上。
- 变更策略：新同事入职开权限，离职回收，临时开放某个端口并记下到期时间。

这些事单独看都很琐碎，但它们共同构成一件事：**减少暴露面，并让每一次变更都可追溯**。

## 四个被改掉的习惯

### 一、默认配置不等于安全配置

以前部署一个服务，跑起来就算完成。现在会先问：默认端口要不要改？默认账号密码换了吗？管理后台是不是暴露在公网？调试接口上线前关了吗？

绝大多数被利用的漏洞，不是什么高深的内存破坏，而是"默认口令没改"和"测试接口忘了关"。

### 二、权限要按最小必要给

做权限回收时最常发现的，是"当年为了赶项目临时开的管理员权限，三年了还在"。写业务代码时也是同一个道理：接口鉴权不要图省事给个 `if (user) return true`，数据库账号不要用 root。

### 三、日志是给未来的自己看的

运维排查最怕"没有记录"。谁在什么时候改了防火墙规则、为什么改、什么时候恢复——没有这些，一次故障排查会变成考古。

写代码时我也开始认真对待日志：**结构化字段、带上请求 ID、记录失败原因**，而不是 `console.log('error')`。

### 四、依赖是有保质期的

第三方库会爆漏洞，镜像会过期，证书会到期。以前 `npm install` 之后就再也不看，现在会关注依赖的更新节奏，至少做到：锁版本、定期看安全公告、能快速升级。

## 把巡检写成脚本

重复的核对工作必须交给脚本，这是我在那段实习里最坚持的一件事。哪怕只是一个生成巡检记录的脚本：

```python
import csv
from datetime import date

CHECKLIST = [
    ('补丁状态', '所有终端与服务器补丁已更新至最新'),
    ('病毒库', '病毒库版本在 7 天内'),
    ('弱口令', '无弱口令账号，无共享账号'),
    ('异常外联', '无内网主机连接未知外部地址'),
    ('权限', '离职账号已回收，临时权限已到期'),
    ('备份', '关键数据备份任务成功'),
]

def write_report(path, operator, note=''):
    with open(path, 'w', newline='', encoding='utf-8-sig') as f:
        writer = csv.writer(f)
        writer.writerow(['日期', '检查项', '标准', '结果', '检查人', '备注'])
        for item, standard in CHECKLIST:
            writer.writerow([date.today().isoformat(), item, standard, '待确认', operator, note])

if __name__ == '__main__':
    write_report('inspection.csv', operator='沈宇轩')
    print('巡检表已生成')
```

脚本本身很简单，价值在于：**它让"今天有没有做巡检"这件事从记忆变成了文件**。有了历史记录，趋势才有意义——比如某台机器的补丁连续三周没打上，这比"今天全部正常"有用得多。

## 对开发者的三点建议

1. **上线前过一遍"暴露面清单"**：公网可访问的端口、开放的接口、默认账号、调试开关、错误堆栈是否外泄。
2. **别把安全当成上线后的事**：鉴权、输入校验、依赖管理都是开发阶段的工作量，越晚补代价越高。
3. **假设会被攻破**：与其追求"绝对进不来"，不如保证"进来之后能被发现、能止损"。这就是日志、备份和权限分离的意义。

## 小结

安全运维不产生新功能，它产生的是**确定性**：知道系统现在是什么状态、谁改过什么、出了问题从哪查。

这段经历没有让我变成安全专家，但让我在写每一行涉及权限、日志、配置的代码时，会多停一秒。这一秒很值。
